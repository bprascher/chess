## 3. Points where the architect may challenge the decisions

These were chosen by judgement. If a design reason argues against one, report it to the systems engineer rather than working around it.

1. **`games.json` (H-02)** reverses the architecture's choice to recompute evaluations after import. The requirement text (DAT-2, "analysis results", accepted under Q75) is the reason. If recompute is preferred, the alternative is to amend DAT-2 so that analysis results are re-created, not exported.
2. **No "replace" for PGN duplicates (H-03)** departs from the literal DAT-2 prompt wording to avoid overwriting a rated, played game. Confirm that the importer can tell a played game from an imported one.
3. **All clocks stop while a draw offer is pending (H-07)**: confirm this fits the clock model in §4.2 and the journal records.
4. **Replay of `done/` journals after a restore (H-16)** assumes re-finalising a game is idempotent and order-dependent only on end time.
5. **`chess install-cli` and the symlink location (H-19)** rest on macOS facts that were not verified here (TBC-10).
6. **Scripted runs are rated by default (H-12)**: the user may prefer unrated by default; that would need an ELO-2 exception.
