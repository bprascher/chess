- `[RAN]` `grep` over the nine SDDs and `architecture.md`/`requirements.md` for each of the eight check areas, then targeted reads of the hit regions. The SDDs were **not read end to end**; a defect outside the hit regions can be missed.
- Line numbers are those of the working tree on 2026-10-31 (the files are uncommitted).
- Not checked: Mermaid validity of the edited diagrams; `test-strategy.md`; the use cases; the architecture §7.2 schema against the store DDL column by column; SQL text; any numeric claim marked `ESTIMATE`.
- Severity: **Major** changes or breaks an interface, a stored format, an edge or a decision text; **Minor** needs a statement, a name or a value. Gate tier is that of the proposed *fix* under CLAUDE.md and SWE-001 §3.

## 3 Items that need Brian's decision

1. **Stored format: `content_hash` in the `GameEnd`, `Abort` and `Voided` journal payloads** (FIND-JR-001). Store OQ-ST-002 and app OQ-APP-005 propose it; the architecture and domain do not have it. G3. Without it, a restore cannot rebuild the hash.
2. **Stored format: `DrawDropped` (and the other empty-looking kinds) payload** (FIND-JR-003). Either the record carries side and cause and the domain `Fact` gains them, or the record carries nothing. G3.
3. **Roster index API** (FIND-JR-008). Does `Store::next_roster_index(class)` return the highest stored index (domain computes *k* with `first_k_after`), or the next *k* (store computes it from index mod 5)? D-46 text says only `next_roster_index(class)`. G2.
4. **ECO for an imported custom start that carries an `ECO` tag** (FIND-JR-012). DAT-3 and Q-SE-5 (confirmed) say keep the file's code with an empty name. Q-SE-24 (not in the confirmed list) says no code and no name. Pick one; then the SE restates the other.
5. **ID policy** (FIND-JR-011). Is zero-padding existing IDs (XC-30) a permitted "normalisation", or does CLAUDE.md's "do not renumber" win? If it wins, domain, engine, rules and store revert and architecture's `EI-EN-02` and the triage's `R-EN-n` stay valid. One prefix family (`FIND-` or `UF-`) should also be chosen.
6. **Typed-move error detail in the catalogue** (FIND-JR-007) and **global event envelope** (FIND-JR-013). Both are protocol shapes (G2). The SDDs already depend on them.
7. **Who owns the calibration run** (FIND-JR-017): `chess-app` or `chess-engine`.

Not for Brian, but needing the System Architect before the next SDD revision: FIND-JR-002 (recovery path, G1), 005, 006, 009, 015.
