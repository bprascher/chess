## 2. New findings introduced by the changed text

| ID | Sev | Finding | Scenario | Fix |
|---|---|---|---|---|
| RR-A-1 | Minor | The rebase does not cover an empty intact run, a final or voided row, or a missing `.jnl` during the rename window. (a) If the header or the `Start` record is the damaged part, "copy the intact run" copies nothing and the synthesized `Move` records start at seq 1. The rebased file then has no `Start`, so replay cannot build the game and the user is offered `VoidUnreadableGame` for a recoverable game. (b) The rebase never says what happens when `GAME.status` is already final or voided (the StoreAhead case where the lost tail held the `GameEnd`). (c) Between the two renames, `<uuid>.jnl` is absent. The D-84 "row with no journal" path would create a new `Start` journal, and the second `rename` replaces it silently. A DB lease probably blocks this (INF, not checked). | Header corruption with MOVE rows present; a `GameEnd` lost from a damaged tail. | State that the rebase synthesizes `Start` from the row when the run lacks it; define the final and voided cases; make the "no journal" path check `.rebase` first and rename with no-replace semantics. |
| RR-A-2 | Minor | D-87 names "`GameEnd` or `Abort` followed by `Voided`". Domain T18 and the §4.3 diagram (l.650) allow `Voided` only from `Completed`. `Aborted --> [*]` has no `Voided` edge, so an `Abort` then `Voided` journal is still a replay error and a false `JournalUnreadable`. Reset-void needs h-h or h-c and `Abort` is c-c only, so the pair is probably unreachable. | Repair appends `Voided` after `Abort`. | Drop "or `Abort`" from D-87, or add the edge in T18 and §4.3. |
| RR-A-3 | Minor | The multi-fact step 5a adopts the durable prefix, but neither it nor the D-82 text says that the adopted records are handed to the store applier (step 6). Resume recovers them from `seq > journal_seq`, so no move is lost. The live DB lags until then. | `Move` durable, `Ended` append fails, process stays up. | One sentence in step 5a. |
| RR-A-4 | Minor | Internal contradiction in D-78 (l.2066): item (4) says "(ASM-10 is still open)" and item (3) says "no record carries it". §14 closes ASM-10, and the proposal says the second claim is overstated for a clean stop. The status note was added and the body was left as is. | A reader of D-78 alone sees ASM-10 as open. | Add "(closed, §14)" in D-78 (4) now. Leave the rest for Brian's choice. |
| RR-A-5 | Minor | The rebase swap syncs "the directory" after each rename. The first rename crosses two directories (`journal/` and `journal/damaged/`). If only `journal/` is synced and the power fails, the damaged file could be overwritten by the second rename. This is a "never deleted" risk, not an acknowledged-move risk. | Power loss between the renames. | Say "sync both directories". |
